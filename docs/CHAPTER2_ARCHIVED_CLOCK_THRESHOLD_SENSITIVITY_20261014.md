# Q2：原本ZIPからのイベント閾値感度解析（2026-10-14）

**対象：すでに実行・独立再生・保存されたModel3パイロット1,536履歴のみ。新たなModel3進化履歴は生成しない。**
この分岐は[PR #521](https://github.com/zuizui0223/izu-core/pull/521)の対応時刻再集計に積み重ねるもので、元の[PR #491](https://github.com/zuizui0223/izu-core/pull/491)とmainの科学的結論は変更しない。

## 目的と事前の採否条件

先行するPR #521では、保証Aの初期遺伝子型半幅を0.046875→0.078125へ広げると、既存の0.05・20連続占有センサスの最初の応答時刻が全768対応ペアで固定上限付き平均51.302更新早まった。一方で、0.05は操作したA対立遺伝子幅の間に位置する。もしこの「早期化」がイベント閾値の選び方に特有なら、そこから「普遍的な進化速度」を推論できない。

**原登録の0.05を変更しないまま**、別の観測定義で結果がどう変化するかを、保存済み年間ゲノムZIP中の各年平均と個体群人数から別実装で計算する。読込以外に原Model3の生物コード・乱数・親子更新・出生・突然変異を一切動かさない。

| 水準 | 占有20時点の形質平均応答閾値 | 用途 |
|---|---:|---|
| 採択済み主判定 | 0.05 | 元の読み出し結果の完全一致ゲート |
| 低閾値 | 0.025 | 小さな変化量なら先行順位が保たれるか |
| 高閾値 | 0.075 | 初期遺伝アクセス幅の上側付近 |
| さらに高い閾値 | 0.10 | 初期A支持だけで届かない判定領域 |

*元の一部別コホート（6,144履歴）にある0.025/0.10感度結果を、この1,536履歴のものと混同していない。今回の3閾値は事後的な診断であり独立した確認試験ではない。*

## 具体的な凍結データと安全契約

1. 元の6 ZIPについて独立保管レシートのSHA256に完全一致するものだけ受理する。ZIPは257個（原本256 NPZ＋完了JSON）、名前・容量・ファイルタイプを検査し、パストラバーサル、重複、欠損を停止させる。標準GitHub公開Releaseを固定URLで取得する。
2. NPZ各1,536件のSHA256は既存の独立 native replay 受入ファイル内の \`case_sha256\`、ZIP内 \`_COMPLETION.json\` の2箇所と突き合わせる。元原本の**再計算済み0.05イベント分類とA/I初開始時刻**は、毎年 \`means\` と \`population\` から再計算したものと一件でも違えば全解析を失敗させる。
3. t=0..200の201回の測定、年181までの20連続占有開始、±5年同時、六分類を固定。未到達・打切り・絶滅も全開始分母に残す。
4. 2創始者背景×3送粉環境×2隠れたI相同状態×64将来乱数IDを**同じ幅L/Hの対応ペア**とし、六分類、A/Iイベント発生数、順序スコアD、6条件別D、全768組の打切り上限182の初開始時刻を、それぞれの閾値について記述集計する。
5. 結果の主判定は前回の元0.05差 **ΔD=+0.6692708333**, Aの全開始上限時刻差 **−51.30208333** の完全再現。その他の閾値は探索的な感度解析として元結果と並置し、原著の「主判定」を上書きしない。
