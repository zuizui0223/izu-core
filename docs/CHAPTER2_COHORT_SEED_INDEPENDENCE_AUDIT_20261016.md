# izu-core — コホート独立性・乱数系列・共通乱数の監査（2026-10-16）

**結論：** 同じ乱数の数値を使うこと自体はバグでなく、「異なる実行済み訪花者コホートで独立の生物学的追試が成立した」と誤って宣言することが問題。既存2設計の共通乱数 `75001–75128 / 301–304` は**実行前の旧設計→最終版への置換**であり、**二つの実行済み独立追試ではない**。別の2026-10-03先行検証は、**74001–74128の元の訪花者履歴を保持して人口反復seedだけ201–204に変更**した実験である。

## 実装した安全ルール

[種と独立性の原資料台帳](CHAPTER2_COHORT_SEED_LEDGER_20261016.json) と [検証コード](../scripts/audit_chapter2_cohort_seed_independence_20261016.py) のルール：

- **実行済み／未実行廃止／探索**を区別する。完了済みの結果ファイル（またはGitHub Actionsで検証された原本結果の説明）がないと実行済みとして数えない。
- 数字が同じでも**創始者／訪花者履歴／人口動態／bootstrap**の乱数namespaceは別扱い。例えば遺伝的創始者`74001`と別実験の訪花者seed`74001`は、これだけで乱数の重複を示さない。
- 同じ生態履歴generatorの**2つの実行済みコホート**が訪花者IDを共有する際は、明示的な**対応実験・人口反復追試の宣言**を要求する。「訪花者履歴が互いに独立」という宣言があればそこで失敗させる。
- 先行設計が「実行前廃止」と明示される場合、後続の最終版と訪花者や人口seedが全く同じでも**2つの独立実験と数えない**。元の設計書を変更せず、廃止先・実行前のタイムスタンプ・結果0件を参照する。
- 同じ訪花者履歴に異なる処理（fixed/evolving A、near/far）を割り付ける**共通乱数による対応比較**は正常な設計なので禁止しない。
- 独立創始者ゲノムを主張する場合は創始者の乱数namespaceの重複を別途チェックする。Q1新しい8創始者は旧Q1一創始者と異なるが、Q1旧実験とQ4実験は**同じ元の創始者seed 74001**を使用するため、両者を独立創始者背景と表現しない。
- 全`data/design/*.json`のseed名前・領域を**静的に棚卸し**するが、これだけで各設計の独立性を自動認定しない。元の実行ソースと結果記録の読み込みは別の作業。

## 旧設計→最終版の誤読を防止

[旧設計](../data/design/chapter2_new_history_generalization_validation_20261003.json) は `status=superseded_before_execution`、`outcomes_generated_under_earlier_design=false` を保存。最終[採用設計](../data/design/chapter2_finite_history_signal_environment_validation_20261004.json)は **2026-10-03 21:32:52 UTC** に凍結され、最初の実行開始は **2026-10-03 21:35:35 UTC**。

両設計のseed集合が完全一致するため、**「独立追試2本のseed重複」という批判は、この組に限っては不正確**。むしろ旧版と採用版を2度別々に数える書き方自体を台帳側で予防する必要がある。

## 科学的な主張の厳格化

- 「独立性が高い」と表現するときは**どの揺らぎについて独立か**を必ず明記する。特に訪花者履歴、創始者ゲノム、人口反復、外生送粉者generator、遺伝子的応答はそれぞれ別。
- 同じ`source`、同じ環境履歴generatorを使った新seed検証は**Model3内のホールドアウト**であり、自然島嶼での外的検証ではない。
- PR #569の「差の縮小」は新創始者×新訪花者履歴で**3/4設定が事前判定に通過**、直接Aコストありは未決。「低送粉側で投資が相対的に保たれる」の元の2設定での符号は再現しなかった。ただし、創始者と訪花者の両軸が変わっているため**符号差の原因を創始者ゲノム単独へ帰属しない**。
- Q4で「履歴に由来する存続効果」を解釈するときは、共通乱数と状態の引継ぎを識別し、Aの進化可能性が**将来80更新も続く**点を維持する。

結果の境界：文書とseedの一致及び実行済みの結果の存在を確認する監査であって、全実験の原生物履歴を独立に再実行するものではない。環境履歴の完全な状態をSHA照合する別の原資料監査と組み合わせる必要がある。
